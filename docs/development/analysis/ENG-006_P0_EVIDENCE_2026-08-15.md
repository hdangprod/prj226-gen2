### 2. Available Fields vs. Required Resumption State
- `AcceptedProjectContext` contains **only** `projectId`, `facts`, and `progress`.
- For full project resumption ([PRODUCT_REQUIREMENTS.md](file:///Users/dangnguyen/Desktop/prj226-gen2/product/PRODUCT_REQUIREMENTS.md) `PI-CAP-002`, `PI-OUT-001`; [SCENARIOS.md](file:///Users/dangnguyen/Desktop/prj226-gen2/product/SCENARIOS.md) `SCN-003`), the interaction layer requires:
  - Project identity and intended outcome (`Project`)
  - Open and completed actions (`Action[]`)
  - Accepted context facts and progress (`AcceptedProjectContext` or `facts[]` + `progress[]`)
  - Current captured knowledge items for the project (`KnowledgeItem[]`)
- `AcceptedProjectContext` **alone is structurally incomplete** to represent the full resumption payload.

### 3. Semantic Impact of Combining Existing Domain Types
- Grouping existing domain types into a composite application-layer read structure (e.g. `{ project: Project, actions: Action[], context: AcceptedProjectContext, knowledge: KnowledgeItem[] }`) requires **no new domain semantics**. It packages existing domain facts.
- Application-layer result structures (like `ProjectActionMutationOutcome` in `projectActionContextService.ts` or `KnowledgeProvenanceOutcome` in `knowledgeProvenanceService.ts`) are standard operational projections.

### 4. Candidate Retrieval Return Type Options (Non-Binding)
- **Option A — Granular Domain Query Methods:**
  ```typescript
  getProject(id: ProjectId): Promise<Project | undefined>;
  listActiveProjects(): Promise<readonly Project[]>;
  getActions(projectId: ProjectId): Promise<readonly Action[]>;
  getAcceptedContext(projectId: ProjectId): Promise<AcceptedProjectContext | undefined>;
  getKnowledge(projectId: ProjectId): Promise<readonly KnowledgeItem[]>;
  getCrossProjectKnowledge(): Promise<readonly KnowledgeItem[]>;
  ```
- **Option B — Composite Application Resumption DTO:**
  ```typescript
  interface ProjectResumptionData {
    readonly project: Project;
    readonly actions: readonly Action[];
    readonly context: AcceptedProjectContext;
    readonly knowledge: readonly KnowledgeItem[];
  }
  ```
- **Option C — Discriminated Query Result Envelope:**
  ```typescript
  type RetrievalResult<T> =
    | { readonly kind: "found"; readonly value: T }
    | { readonly kind: "not-found"; readonly entityId: string }
    | { readonly kind: "failed"; readonly reason: string; readonly retryable: boolean };
  ```
